# cody-jepa — repository review

**Date:** 2026-08-12 · **Reviewed at:** `0419874` (main, clean tree) · **Scope:** all 1,591 lines of Python in the repo, plus the git-ignored `outputs/` archive and the two refactor commits that produced the current state.

---

## 1. Summary

The code is clean, small, and readable — genuinely so. Every file does one thing, the tests are end-to-end on a synthetic corpus, and CI runs them. As an engineering artifact this is in good shape.

The research it implements is not working, and the repo no longer contains the evidence that shows why.

Three findings, in order of importance:

1. **The pretext task is close to degenerate.** ~90% of masked prediction targets are empty background. I measured this on the sample silhouettes shipped in `data/healthgait/archives/`: after `data.py`'s resize, a mean of **9.2% of the 196 patches contain any foreground** (17.9 of 196). The archived diagnostic independently measured 9.6% on the real training set. Most of the loss is "predict that this region is blank," which is solvable from the position embedding alone.

2. **The archived diagnostics confirm the predictor ignores its context.** In `outputs/phase0/baseline/context_use.metadata.json`: substituting an **all-zero blank video** for the context changes the loss by 9.5e-5; substituting a *different subject's* clip changes it by 1.56e-4. The same-subject-minus-cross-subject contrast has 95% CI **[-6.9e-6, 1.6e-5]** — indistinguishable from zero across 80 subjects. The model cannot tell whose gait it is looking at. Temporal shuffling of the context hurts *less* than a blank video (4.8e-5).

3. **The anti-collapse regularizer is guarding the wrong axis.** Same file, `d3`: context-token effective rank is **380.8 / 384** (99% — VICReg's own target, healthy), while the clip-level pooled representation the probes actually consume is **11.5 / 384** (3%). `vicreg()` is called on `context_tokens` flattened `(B,N,D)→(B·N,D)`, so it enforces variance *across tokens*, not across clips. It reports green while the thing you evaluate is collapsed.

These three are one causal chain, and they explain the flat `phase1` grid: all eleven variants land at gait 0.88–0.94 and identity 0.06–0.11. Learning rate, EMA schedule, mask scale and predictor depth all leave the results unchanged because none of them touch the failure mode.

**The 93% `gait_system` score is not evidence that any of this works.** It is a 2-class problem, it is flat across every variant including the ones whose identity accuracy halves, and there is no random-init control anywhere in the current code to bound it.

## 3. Correctness bugs in the current code

Ordered by consequence. Line numbers at `0419874`.

### P0 — silently corrupts results

**`data.py:127` — full uncropped frame squashed to a square.**
```python
image = image.resize((self.image_size, self.image_size), Image.Resampling.BILINEAR)
```
Source frames are 960×540. There is no person crop, no tracking normalization, and no aspect preservation — a **1.78× horizontal squash**. The subject's bounding box is a median 300×132 px in the original, so after the resize the person is roughly 62×15 px inside a 112×112 input. This is the root cause of finding #1. Everything downstream inherits it.

**`engine.py:263` — VICReg applied to the wrong axis.**
```python
variance, covariance = vicreg(context_tokens.float(), var_gamma)
```
`vicreg()` reshapes `(B, N_ctx, D) → (B·N_ctx, D)`. Token-level variance is preserved; clip-level variance is not constrained at all. Empirically: 381/384 vs 11/384. Either add a clip-level term (`context_tokens.mean(dim=1)`) or, at minimum, log the clip-level effective rank so the training-time health metric matches the evaluation-time representation.

**`engine.py:124` vs `evaluation.py:46` — you monitor one representation and evaluate a different one.**
Training-time `collapse_metrics` pools `context_encoder(video)` *after* the final LayerNorm. Probes pool `target_encoder(..., return_pre_norm=True)[1]` — different encoder, before the LayerNorm. The `eff_rank` printed each eval epoch is not the effective rank of the features you probe.

**No random-init control exists.** Given §1, this is the single most important missing number in the repo. A frozen randomly-initialized ViT of the same geometry, run through `export_features.py` → `probe.py`, would take under an hour and would tell you whether JEPA training contributes anything at all to the 93%.

### P1 — breaks specific workflows

**`engine.py:221` — `--resume` restarts every schedule.**
```python
history = []
best_loss = math.inf
global_step = 0          # ← after the resume block
```
Resuming restores epoch but not step. Consequences: the LR warmup runs again from `start_lr`, the EMA momentum schedule restarts at `ema_start`, `best.pt` is overwritten by the first post-resume eval regardless of whether it is worse, and `train.py:48` overwrites `history.json` with only the post-resume tail. `save_checkpoint` stores none of `global_step`, `best_loss`, or `history` — all three need to go into the checkpoint dict.

**`evaluation.py` — probe statistics are computed per window, not per recording.**
`export_features.py` defaults to `--windows 3`, so `_metrics` reports `val_examples` as 1,872 windows drawn from 624 recordings. Three windows of one recording are not independent samples. Any confidence interval computed from these counts is roughly √3 too narrow. Aggregate to the recording (or subject) level before scoring.

**`evaluation.py:106` — numerical warnings suppressed.**
```python
warnings.filterwarnings("ignore", message=r"(?:divide by zero|overflow|invalid value) encountered in matmul", ...)
```
On 384-d features with a collapsed spectrum, overflow in the solver's line search is a signal about conditioning, not noise. At minimum count and report the suppressions.

**Probe regularization is untuned and unreported.** `LogisticRegression(max_iter=2000, class_weight="balanced")` uses the default `C=1.0`. On 384-d features with an effective rank of 11, `C` will move the score more than any of the eleven `phase1` ablations did.

**`evaluation.py:135` — identity is never measured on held-out participants.** `probe_identity(..., split="train")` is the default and `run_probes` never overrides it. Combined with the dropped retrieval probe, the repo currently has no open-set biometric measurement at all.

### P2 — worth fixing, not urgent

- **`masks.py:41`** — masking is purely spatial, replicated across all 8 temporal tokens. Context and target both span the full clip. This matches V-JEPA, so it is defensible, but it means the pretext task never asks about temporal structure — and neither do either of the probes. For gait that is a strange place to end up. The archived `temporal_shuffle` gap (4.8e-5, *below* the blank-context gap) is the empirical confirmation.
- **`masks.py:84-89`** — `rng.sample(...)` trims context and target to the batch minimum, so effective context size varies with batch composition. Harmless for correctness, adds variance.
- **`engine.py:102`** — `collapse_metrics` returns `effective_rank = 0.0` for a fully constant representation, while the docstring and README both say it "collapses toward 1." `test_pipeline.py:150` enshrines the `0.0`. Fine today; a real trap if you ever gate on a minimum rank.
- **`engine.py:32`** — `autocast` silently returns `nullcontext` on MPS. `configs/healthgait.json` declares `"amp_dtype": "bfloat16"`, so the same config runs bf16 on CUDA and fp32 on Apple silicon with no warning. The `phase0` runs were on MPS.
- **`engine.py:224`** — `steps` is checked only at epoch boundaries, so a run overshoots by up to one epoch.
- **`engine.py:271`** — the trailing partial accumulation group is still divided by `accumulation`, giving a smaller effective step at each epoch end.
- **`engine.py:144-145`** — `evaluate()` unconditionally calls `.train()` on exit, even when the caller passed models in eval mode.
- **`engine.py:169`** — `torch.load(..., weights_only=False)`.
- **`build_manifest.py:46-47`** — `gait_system` and `speed` are always identical. Drop one.
- **`train.py`** — no `--seed` flag, no multi-seed support. Every number in the repo is single-seed and there is no mechanism for error bars, though `outputs/phase0/regen-r1..r4` shows you previously did repeats by hand.

## 4. Recommended order

1. **Restore `diagnostics.py` from `archive/pre-refactor`** and re-run the context-substitution gap on any current checkpoint. It is the fastest way to know whether a change did anything. Make it part of the eval loop, not a separate archived script.
2. **Add a random-init control row** to `probe.py`. Until that number exists, no probe result in this repo can be interpreted.
3. **Fix the input pipeline** — person crop (or aspect-preserving letterbox) plus tracking normalization in `data.py`. Target foreground patch coverage well above 10%. This is the one change with a plausible path to moving finding #2.
4. **Add clip-level rank** to `collapse_metrics`, computed on the same representation the probes use, and either extend VICReg to the clip axis or stop describing it as the anti-collapse guard.
5. Fix the resume bug and switch probe statistics to the recording level.
6. Then re-run a *small* ablation grid. The eleven-run `phase1` sweep found nothing because it varied parameters that cannot affect the failure mode; repeating it before 1–4 will find nothing again.

One structural note: the deleted `iclr2027-direction.md` recommends pivoting to counterfactual probing on the Health&Gait 2×2×2 within-subject design, explicitly because it needs **no new pretraining**. If that is still the plan, items 1, 2 and 4 above are still required (you need a random-init control and an honest collapse measure to make any probing claim), but item 3 becomes less urgent. Worth deciding which track you are on before spending compute — the two imply different priorities.
